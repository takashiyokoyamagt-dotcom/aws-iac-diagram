# フェーズ 4（配置と .drawio）の設計案

- 状態: 案（2026-11-08）。判断が要る点は 8 章に推奨を書き、**ユーザーの「判断は推奨で進める」の指示に従って推奨で進める**。覆したいものがあれば、手順 1 の実装の前に言ってもらえば直す。
- 根拠: PLAN の 5 章のフェーズ 4 行、B1・B2・C5、CRITERIA の 2 章・3 章。入力は normalized IR（ir-schema 1〜6 章）。

## 1. 完了基準（CRITERIA 2.2・2.3 の .drawio の分、3 章）

- 全入力（golden の 101 ケースの normalized IR）で、重なり・はみ出し・貫通・ラベルの重なり・壊れたアイコンの使用が 0 件。L4（T17・T19・T20）の貫通だけ、図 1 枚ごとに辺の本数の 5% 以下。
- 1 枚の図のアイコンのノードは 40 以下（超えるときは分割）。
- B1: 選んだ候補のスコアが全候補で最小（同点は候補名の辞書順）。
- 2.3: 各ビューが IR の部分集合で、全体図（分割の和集合）に全ノード・全辺が出る。推定の辺は破線、導出の辺はラベルつき、推定があれば凡例。`.drawio` の XML の形（失敗知見 7〜11）。B2 の 3 ビューが出る。`coverage.md` が網羅分類と一致する。
- C5: 同じ入力は 2 回・両 OS でバイト単位で同じ。

## 2. 構成

```
normalized IR
  → layout/views.py    ビュー（全体・ネットワーク・詳細）と分割を決める
  → layout/tree.py     ビューの入れ子の木（region / vpc / az / subnet / 素のノード）
  → layout/grid.py     1 候補の座標（内側から大きさを積み上げる。相対座標）
  → layout/score.py    交差数・折れ数・総延長・縦横比
  → layout/search.py   候補を列挙して B1 で選ぶ
  → emit/drawio.py     mxfile の XML（図形レイヤと辺レイヤ、背景矩形、凡例）
  → emit/coverage.py   coverage.md
  → validate/drawio.py CRITERIA 2.1 のモデルで検査（layout を import しない。出力の XML だけを読む）
入口: scripts/diagram.py（--input <ir> --out-dir <dir>）、scripts/validate_drawio.py
```

層の向き: `layout` → `core`、`emit` → `layout`・`core`、`validate` → `core`。`tests/architecture` の表に足す。外部ライブラリは使わない（標準ライブラリだけ。C5 を守り、PEP 723 の依存を増やさない）。

## 3. 配置の方式（推奨: 自前のグリッド。ELK は採らない）

- 入れ子の枠の中を、内側から再帰的に「子の矩形を行・列に並べて自分の大きさを決める」方式で計算する。座標は整数のみ（浮動小数を出さない）。
- 枠の中の子の並びは、深さで分ける: VPC の中は AZ を横に、AZ の中はサブネットを縦に（public → private → その他の順）。サブネットの中のノードは 1 行あたり最大 N 個。
- 枠の外（グローバルなサービス、internet）は VPC の左右の帯に置く。入口（internet・CDN・DNS・API）を流れの上流の帯、データ（S3・DynamoDB など）を下流の帯にして、辺が枠を横切る回数を減らす。
- 貫通を避けるための余白: ノードの間隔はアイコン幅より広く取り、行と列の間に通路（ガター）を必ず残す。`orthogonalEdgeStyle` に waypoint を置かない（失敗知見 5）。
- ELK: Python だけで動かない（Node が要る）うえ、入れ子を保つには `INCLUDE_CHILDREN` が要り、決定論の確保が別の課題になる。**採らない**（PLAN の「試し、採否を決める」は、この理由で試さずに否と決める案。8 章の 1）。

## 4. B1 の候補とスコア

- 候補: 向き（LR／TB）× 帯の中の順（名前順、辺の次数順、上流からの層の順）× サブネットの中の行の幅（2 通り）の 12 個以内。候補名は `lr-layer-w4` のような固定の文字列。
- スコア: `貫通 × 10000 + ラベルの重なり × 1000 + 交差数 × 100 + 折れ数 × 10 + 総延長 / 10 + 縦横比の 16:9 からのずれ × 10`（整数に丸める）。経路は CRITERIA 2.1 の 4 通りのモデルで、最小のものを使う。貫通を最優先にする。
- 計算量: ノード 60 × 候補 12 でも辺は 20 本未満で問題ない（最大は 59 ノード・17 辺）。

## 5. B2 のビュー

| ビュー | 出すもの |
|---|---|
| 全体図 (`overview`) | 描くノードと辺のすべて。枠は VPC まで（AZ・サブネットを畳んで VPC の直下に並べる）。40 を超えたら VPC／スタック単位で分割 |
| ネットワーク図 (`network`) | 枠（VPC・AZ・サブネット）すべてと、ネットワーク系のノード（規則表の型の行に `view` の列を足す。IGW・NAT・LB・VPCE・ルート） |
| 詳細図 (`detail`) | 全ノードを AZ・サブネットの枠の中に置く。40 を超えたら VPC／スタック単位で分割 |

ファイル: `<name>.overview.drawio` など、ビュー 1 つにつき 1 ファイル（分割のときは `-1`、`-2`）。

## 6. .drawio の形

- 失敗知見 7〜11（必須のセル `0`・`1`、`background` 属性を書かない、コメントに `--` を入れない、圧縮しない、背景の矩形は最背面）を生成のテストで固定する。
- レイヤ: `0` → 背景のレイヤ・図形のレイヤ・辺のレイヤの順に `1` の代わりの親セルを置く。辺の親は常に辺のレイヤ（PLAN の決定）。図形は親の枠からの相対座標。
- アイコンの style は辞書（`data/icons/catalog.json`）の値をそのまま使い、`find_aws_icon` と同じ索引で引く。系統ごとの `strokeColor`（失敗知見 2）をテストで固定する。
- 確信度: 確定は実線、導出は実線＋ラベル、推定は `dashed=1`。XML の属性の順と id は決定論（ノードは IR の id、辺は IR の id）。

## 8. 判断（推奨で進める）

1. ELK は採らず、自前のグリッドにする（3 章）。
2. 規則表に `view` 列を足す（凍結は IR の内容についてのもので、表示の列は ir-schema 8 章で「フェーズ 4 で規則表の列で決める」としている）。
3. 検査（`validate/drawio.py`）を配置より先に作り、配置のコードを import しない（出力を独立に検査する）。
4. L4 の 5% は仮の値のまま（ユーザーの微調整は CRITERIA 7.1 のとおり一度だけ、後で）。
5. 日本語のラベルの選択（B3）はフェーズ 4 では作らない（ノードのラベルは IR の値を使う）。
