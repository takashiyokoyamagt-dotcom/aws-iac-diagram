## 7. アダプタの出力（`stage: "raw"`）

アダプタは、入力（CFN のテンプレート、cdk.out、TF の .tf／plan JSON）を読み、A4 の評価を済ませた後のリソースと参照の一覧を出す。**図の形（ノード・辺・入れ子・網羅分類）にはしない。** それは正規化（フェーズ3）の仕事で、規則表（resource-catalog.md・relation-resources.md・edge-rules.md）を使うのも正規化だけにする。ただし、A5 の要約表（読まないレジストリモジュールの中身を作る表）はアダプタが使う（中身のリソースを `resources` に載せるため）。CFN と TF で同じ形にし、正規化を1つにする。

この章の形は、CFN アダプタ（`scripts/adapt_cfn.py` と `scripts/aws_iac_diagram/adapters/cloudformation/`。フェーズ1 の手順2〜4）の実装で確かめ、手順5 で確定した（2026-10-17）。CFN では、自作 fixture と公開サンプルの CFN（入力 25、cfn-lint の辺 513 本）で、cfn-lint のグラフの辺のすべてに参照が対応した（CRITERIA の 1.6）。TF アダプタ（`scripts/adapt_tf.py`、`scripts/aws_iac_diagram/adapters/terraform/`。フェーズ2）でも同じ形で足りた。足りなかったもの（TF だけのフィールド `provider`・`region`、TF の props・参照・値の書き方、モジュールの展開、plan JSON の入力）は、7.1〜7.5 の該当のところに書いてあり、フェーズ2 の手順5 で確定した（2026-10-26）。公開サンプルの TF のルート 52 フォルダと `.tf` のあるフォルダすべて（205）が、検査を通る raw IR になる（`aws-iac-diagram-workspace/tools/tf_public_check.py`）。

### 7.1 全体の構造

```json
{
  "ir_version": "1.0",
  "stage": "raw",
  "format": "cfn",
  "root": "fixtures/cfn/three-tier/template.yaml",
  "evaluation": {"parameters": {"EnvType": "dev"}, "conditions": {"IsProd": false}, "assumptions": ["…"]},
  "resources": [ … ],
  "references": [ … ],
  "diagnostics": [ … ]
}
```

| キー | 内容 |
|---|---|
| `format` | `cfn`／`tf` |
| `root` | 入力のパス。`aws-iac-diagram-workspace/` からの相対パス（ツールとして使うときは、作業中のフォルダからの相対パス）で、`/` 区切り（C5。OS によらず同じにする）。CFN は最上位のテンプレートか cdk.out のディレクトリ、TF はルートモジュールのディレクトリ（plan JSON だけを読んだときは plan JSON のファイル） |
| `evaluation` | 評価に使った値。CFN は `parameters`（使った値。外から渡した値か Default）と `conditions`（すべての条件の評価の結果。決まらなければ `null`）、TF は `var_files`（読んだ変数のファイル。読んだ順に、`root` からの相対パス）と `vars`（宣言したすべての変数の、値の出どころ。`{"source": "env/dev.tfvars"}` のように、値を取った変数のファイルの名前・`"--var"`・`"default"`、plan JSON の `variables` から取った値は `"plan"`（7.2 の「TF の plan JSON」）、値が無ければ `null`。手元のローカルモジュールの変数は、名前の前にモジュールのパスを付け（`module.app.environment`、`module.m[0].name`）、呼び出しの引数で渡したものは `"argument"`（要約表から展開したモジュールの変数は書かない）。値を使わない変数には `"hidden": "sensitive"`／`"ephemeral"`／`"redact-var"` を足す。**値は書かない**（秘密の値を IR に残さないため。2026-10-17 にユーザーが決定）。`props` には評価した値が入るので、`sensitive` を付けていない変数の値は props に入りうる）。`assumptions` は読み替えや既定値の採用などの前提（書いた順）。ネストスタックと cdk.out の複数スタックでは、名前の前にスタックのパスを付ける（7.2 の address と同じ形。`NetworkStack/HasNat`、`App::IsProd`）。最上位のテンプレートの名前には付けない |
| `resources` | 入力の**すべての**リソース（7.2）。網羅分類（A6）の元になる |
| `references` | リソースからリソースへの参照の一覧（7.3） |
| `diagnostics` | 読めなかった・評価できなかったものの記録（7.5） |

### 7.2 リソース

```json
{"address": "AppService", "type": "AWS::ECS::Service", "file": "template.yaml", "enabled": true,
 "props": {"ServiceName": "demo-app", "Cluster": {"$res": "Cluster", "attr": null},
           "LoadBalancers": [{"TargetGroupArn": {"$res": "AppTargetGroup", "attr": null}, "ContainerPort": 8080}]}}
```

| フィールド | 必須 | 内容 |
|---|---|---|
| `address` | ○ | 網羅分類と同じ形（4章）。CFN のネストスタックの中は `<親の論理ID>/<論理ID>`。cdk.out など**複数のスタック**を読むときは、先頭に `<スタック名>::` を付ける（`App::Vpc`、`My-App::NetworkStack/Vpc`。スタック名は英字で始まり、英数字とハイフンだけ）。スタック名は manifest の `stackName`（無ければ artifact の ID）で、同じ `stackName` が2つ以上あるときは artifact の ID を使う。CDK の Stage（入れ子のアセンブリ）の中のスタックも読む。TF はインスタンスアドレス（値が決まらない count は `[*]`） |
| `type` | ○ | 入力のままの型。TF の黒箱のモジュールの呼び出しは `module` |
| `file` | ○ | ファイルのパス。`root` がディレクトリならそこからの相対、ファイルならそのファイルのあるディレクトリからの相対（`/` 区切り。ルートの外は `../` 付き。4章） |
| `enabled` | ○ | 作られるか。`true`／`false`（CFN の `Condition` が偽、TF の count が 0）／`null`（決まらない）。`false` のリソースも一覧に残し、`props` と参照も同じように出す（網羅分類で `H-COND-FALSE` にし、C1 で参照を照合するため）。正規化は `null` のリソースを描き、`diagnostics` に「条件が決まらない」と残す。ネストスタックの子のリソースは、親のスタックのリソースの値を引き継ぎ、自分の値との弱い方（`false` > `null` > `true`）にする |
| `props` | ○ | 評価した後のプロパティ（CFN は `Properties`、TF は属性とブロック）。値の書き方は下の表 |
| `multiplicity` | | count／for_each の値が決まらないときだけ `"N"` |
| `via` | | `nested_stack`（ネストスタックの子テンプレートから読んだ）、`module_summary`、`module_blackbox`（4章） |
| `implicit` | | SAM が暗黙に作るリソース（`Events` に `RestApiId`／`ApiId` が無いときの `ServerlessRestApi`／`ServerlessHttpApi` など）なら `true`。address は SAM が付ける論理ID。網羅分類にも載せる |
| `module` | | TF だけ。モジュールの中のリソースなら、モジュールのパス（`module.vpc`） |
| `source`, `version` | | TF の黒箱のモジュールの呼び出しだけ。モジュールの source と version（`props` はモジュールの入力） |
| `provider` | | TF だけ。メタ引数 `provider = aws.<alias>` を指定したリソース・data の provider（`aws.us_east_1`）。既定の provider（alias の無いもの）では書かない |
| `region` | | TF だけ。リソースが置かれるリージョンが文字列で決まるとき、その値（CloudFront の証明書の `us-east-1` など）。AWS provider v6 のリソースの引数 `region` があればそれを、無ければ `provider` の provider の設定の `region` を使う（Terraform と同じ優先順）。決まらなければ書かない。どちらも無いリソースは、ルートの既定の provider のリージョン（どのリージョンかは IR に持たない。CFN のスタックと同じ）。モジュールの中のリソースは、provider を呼び出しの `providers` 引数と既定の provider の引き継ぎでたどり、設定のある provider で決める（7.2 の「TF のモジュール」）。正規化は `region` の値で別のリージョンかを見分け、`provider` の alias の名前（`aws.primary` など、同じリージョンを指す alias もある）だけで別のリージョンとして扱わない |

**`props` の値の書き方**

評価できたものはふつうの JSON の値にし、できなかった部分だけ、`$` で始まるキーを持つオブジェクト（印）にする。入力にもともと `$` で始まるキーがあるとき（API Gateway のモデルの `$schema`、EventBridge のパターンの `$or` など）は、`$` をもう1つ付けて書く（`$schema` → `$$schema`）。読む側は、`$$` で始まるキーの先頭の `$` を1つ外して元に戻す。

| 印 | 意味 | 例 |
|---|---|---|
| `{"$res": "<address>", "attr": <属性名か null>}` | 入力の中のリソースへの参照。CFN の `Ref` は `attr: null`、`Fn::GetAtt` は属性名（`!GetAtt A.B.C` は `B.C`）。TF は参照した属性名（`id`、`arn` など） | `{"$res": "OrdersTable", "attr": "Arn"}` |
| `{"$pseudo": "<名前>"}` | 擬似パラメータ。CFN の `AWS::Region`、`AWS::AccountId`、`AWS::Partition`、`AWS::StackName`、`AWS::StackId`、`AWS::URLSuffix`、`AWS::NotificationARNs`。TF の `data.aws_region`、`data.aws_caller_identity`、`data.aws_partition` の値も、同じ CFN の名前（`AWS::Region` など）で書く（ARN の照合を TF と CFN で揃えるため）。`AWS::NoValue` はプロパティ（リストなら要素）ごと消す | `{"$pseudo": "AWS::Region"}` |
| `{"$concat": [ … ]}` | 文字列と印をつないだもの（`Fn::Sub`、`Fn::Join`、TF の `"${…}"`）。正規形: 隣り合う文字列は1つにつなぐ、空文字は消す、印を1つ以上含む（印が無くなればただの文字列にする）、`$concat` を入れ子にしない。要素は文字列と、`$concat`・`$json` 以外の印だけ | `{"$concat": ["arn:aws:s3:::", {"$res": "Docs", "attr": null}, "/*"]}` |
| `{"$json": <値>}` | JSON の文字列として渡す値（TF の `jsonencode(...)`、CFN で JSON を文字列で書く `!Sub '{"Rules": …}'` など）。中身は構造のまま、印を使って書く。CFN の文字列は、`${…}` を置き換えた上で JSON として読めたときだけ `$json` にし、読めなければ `$concat` のまま。**印の無いふつうの文字列も、`{` か `[` で始まり JSON のオブジェクトか配列として読めれば `$json` にする**（同じプロパティが、値によって文字列になったり `$json` になったりしないように。TF の `jsonencode` も、値が全部決まるときを含めて同じ）。文字列の途中に入る JSON（`$concat` の要素）は `$unknown` | `{"$json": {"Statement": [{"Resource": {"$res": "Docs", "attr": "Arn"}}]}}` |
| `{"$az": <0 始まりの番号か "*">}` | 静的に決まらない AZ。`!Select [0, !GetAZs '']`、`data.aws_availability_zones.x.names[0]` は番号（整数で書く）。`!GetAZs ''` だけ、`names` 全体は `"*"`（すべての AZ）。2章の `az1` の元 | `{"$az": 0}` |
| `{"$import": "<エクスポート名>"}` | 入力の中で解決できなかった `Fn::ImportValue`。解決できたもの（cdk.out の別のスタックが Export しているなど）は、エクスポートした値（`$res` など）に置き換え、参照の `fn` を `ImportValue` にする（7.3） | `{"$import": "shared-vpc-id"}` |
| `{"$unknown": "<理由>"}` | 評価できなかった値（値の無いパラメータ、`AWS::SSM::Parameter::Value<…>` 型のパラメータ、`{{resolve:…}}`、未対応の関数、plan JSON の「known after apply」など）。中にあった参照は `references` に `state: "unevaluated"` で残す（7.3）。同じ理由を `diagnostics` にも書く | `{"$unknown": "parameter KeyName has no value"}` |

- **A4（CFN）:** パラメータの値は、外から渡した値（アダプタの `--param`・`--param-file`）→ `Default` の順に使う。`AllowedValues` に無い値は診断に出す。擬似パラメータ（`AWS::Region` など）に渡した値は、条件の評価にだけ使い、`props` は `$pseudo` のままにする（TF と ARN の照合を揃えるため）。条件（`Fn::Equals`・`Fn::And`・`Fn::Or`・`Fn::Not`・`Condition`）は、真・偽・決まらない（`null`）の3つの値で評価する（`And` は偽が1つでもあれば偽、`Or` は真が1つでもあれば真、それ以外で決まらないものがあれば決まらない）。`Fn::Equals` は値を文字列にして比べる。`Fn::ForEach` は、コレクションが決まれば展開し（`${Id}`・`&{Id}`・`Ref Id` を置き換える）、決まらなければテンプレートの1つだけを `multiplicity: "N"` で出す（address は 2章の `Bucket*` の形）。値の真偽値は YAML 1.1 のとおり読む（`yes`・`on` なども真偽値。cfn-lint と同じ）。マップのキーは元の文字のまま読む（`Yes:`・`On:`・`1:` も文字列の名前として残す）。名前の位置（`Condition:` の値、`Ref`）に真偽値として読まれた値は、同じ文字の名前（`Yes`・`On` など）が1つだけあればそれに戻す。パラメータの値が `null`（CLI の `UsePreviousValue`）のときは渡されていないものとして `Default` を使う。SSM の型（`AWS::SSM::Parameter::Value<…>`）のパラメータは、値を渡されても `$unknown`。`Fn::FindInMap` のキーは文字列で引き、キーの評価には擬似パラメータの値も使う（リージョンごとの表を引くため。マップの値は参照を含まない）。`Fn::ForEach` はプロパティの中と `Outputs` の中でも展開する。展開した名前が重なったら後のものを診断を出して飛ばし、×N の名前が重なったら後ろに `.<ForEach の名前>` を付けて両方残す。
- **A4（TF）:** 変数の値は Terraform と同じ順に重ね、後のものが優先する: `default` → `terraform.tfvars` → `terraform.tfvars.json` → `*.auto.tfvars`・`*.auto.tfvars.json`（ファイル名の順）→ アダプタの `--var-file`・`--var`（指定した順）。環境変数 `TF_VAR_*` は読まない（同じ入力から同じ IR を出すため。要るときは `--var` で渡す）。`--var` の値は、`type` が `list`・`set`・`map`・`object`・`tuple` の変数なら HCL の式として読み、それ以外は文字列のまま（Terraform の `-var` と同じ）。値は `type` に合わせて変換する（`"2"` → `2`、`object` の `optional` の既定値、型に無い属性を落とす。変換できない値はそのまま）。`sensitive = true`・`ephemeral = true` の変数と、アダプタの `--redact-var <名前>`（何回でも指定できる）で指定した変数の値、`sensitive()` に渡した値は使わない（`$unknown`、診断 `TF-SENSITIVE-VAR` は info。中の参照は `unevaluated` で残す。パスワードなどを IR に書かないため）。`--redact-var` の名前が宣言に無ければ `TF-VAR-UNDECLARED`（warn）。値の無い変数は `$unknown`（`TF-UNRESOLVED-VAR`）で、使ったところごとに診断を書き、ほかに値の無い変数と、自動では読まれない変数のファイル（ルートとその1つ下のフォルダの `*.tfvars`。`env/dev.tfvars` など）の候補を1つの診断（`TF-UNRESOLVED-VARS`、info）にまとめる（どの環境の図かを確かめるため。CRITERIA の 6）。宣言の無い変数に渡した値は `TF-VAR-UNDECLARED`。locals、テンプレート（`${…}`、`%{if}`・`%{for}`、`~`）、条件式、演算、for 式（`if`、`...`）、組み込み関数（`scripts/aws_iac_diagram/adapters/terraform/evaluator/functions.py` の一覧。`try`・`can` を含む）を評価する。決まらない値（リソースの属性など）を含む演算・関数は、構造だけで決まるもの（`length`・`concat`・`merge`・`lookup`・`element`・`join`・`format` など）は印を残したまま評価し、それ以外は `$unknown`（中の参照は `unevaluated`）。Terraform なら誤りになる式（無いキー、範囲外の添字、1024 個を超える `range` など）は `$unknown`（`TF-EVAL-ERROR`）。未対応の関数は `TF-UNSUPPORTED-FUNCTION`。数の演算は10進で計算する（`0.1 + 0.2` は `0.3`。Terraform の数は任意精度で、Python の float とは違うため。精度は34桁）。`can(x)` は、`x` の値の全体が決まらなければ `$unknown`。count に文字列の数（`"2"`、型の無い変数に `--var` で渡した値）を渡したら数に変換する。
- **TF の count・for_each:** 値が決まればインスタンスごとに出す（address は `aws_subnet.private[0]`・`aws_vpc_endpoint.interface["ssm"]`。for_each のキーは名前の順、キーの書き方は JSON の文字列と同じ）。`count.index`・`each.key`・`each.value` はインスタンスごとの値。count が 0・for_each が空のブロックは、添字の無い address の1件を `enabled: false` で出す（CFN の `Condition` が偽と同じ。網羅分類の `H-COND-FALSE`）。`props` と参照も出し（`count.index` などは `$unknown`、診断は info）、作られないブロックへの参照（`aws_security_group.bastion[0].id`）は、その添字の無い address への `$res` にする。値が決まらなければ ×N（address は `[*]`、`multiplicity: "N"`、`enabled: null`、診断 `TF-COUNT-UNRESOLVED`（warn。ブロックに1つ）。×N と作られないブロックの `count.index`・`each.*` を使ったところは `TF-COUNT-INDEX`（info）。count・for_each の式の中の参照は `unevaluated` で `count`・`for_each` の位置に残す）。決まった count・for_each の式の中の参照は残さない（CFN の `Fn::ForEach` と同じ。値は `each.value` などを通って props の参照に現れる）。`depends_on` は、先のすべてのインスタンスへの参照にする。`dynamic` ブロックは for_each が決まれば展開し（`iterator`、入れ子の `dynamic` も）、決まらなければ `$unknown` の要素1つ（中の参照は `unevaluated`）。module の呼び出しも同じく展開する（下の「TF のモジュール」）。
- **TF のそのほかのブロック:** `check` ブロックの中の `data`（scoped data source）は、ふつうの `data` と同じ address で読む（`assert` は読まない）。`ephemeral` ブロックは state に残らないので `resources` に載せず、`ephemeral.*` への参照は `$unknown`（`TF-EPHEMERAL`、info）にして、ブロックの中の参照を `unevaluated` で残す。`override.tf`・`*_override.tf` は、ほかのファイルをすべて読んでから名前の順に重ねる（Terraform の規則。属性は置き換え、入れ子のブロックは同じ種類のものをすべて置き換える。重ねたことは `evaluation.assumptions` に書く。重ねる先の無いブロックは `TF-OVERRIDE-UNMATCHED`）。`.tf.json` は .tf だけでは読まない（`TF-TFJSON-UNSUPPORTED`、warn。モジュールのフォルダの中も同じ。入れ子のブロックと属性の区別に provider のスキーマが要るため。公開サンプルには無い。フェーズ2 の手順5 で、この扱いのままにすると決めた。理由は8章）。`lifecycle` の `replace_triggered_by` と `provisioner`・`connection` の中の参照は、辺にしない（図の辺は属性の参照から作る）ので `references` に出さない。plan JSON を一緒に渡すと、`.tf.json` のブロックは plan から取り（plan の `configuration` は Terraform が provider のスキーマで読んだ後の形なので、ブロックと属性が区別されている）、`file` は `.tf.json` のファイル名にする。このとき `TF-TFJSON-UNSUPPORTED` は info（下の「TF の plan JSON」）。
- `Fn::If`、`Fn::FindInMap`、`Fn::Select`、`Fn::Split`、`Fn::Equals` などは、値が決まれば評価して結果だけを残す。条件が決まらない `Fn::If` は `$unknown`。評価で選ばれなかった値（`Fn::If` の選ばれなかった側、`Fn::Select` で選ばれなかった要素、`Fn::FindInMap` で引かなかったキーなど）の中にあった参照は、`references` に `state: "pruned"` で残す（cfn-lint は条件を評価せず、これらも辺にするため）。TF では、条件式（`%{if}` を含む）の選ばれなかった側、`try` で使わなかった式と誤りになった式、要素や引数から選ぶ関数（`coalesce`・`coalescelist`・`element`・`slice`・`one`）とリストの添字で選ばなかった要素、for 式の `if` で除いた要素の中の参照を、その属性の位置に `pruned` で残す。同じブロックへの参照が値に残っていれば（属性やインスタンスの添字が違っても。`element(aws_subnet.p[*].id, count.index)` で選ばなかった別のインスタンスなど）`pruned` にしない。マップ・オブジェクトのキーや属性で引かなかった値（`each.value.x`、`local.cfg["a"]`、`lookup`）の中の参照は残さない（CFN の `Fn::FindInMap` のマップは参照を含まないので、数が増えるだけになるため）。
- **リストの分割:** `Fn::Split` と、`List<…>`／`CommaDelimitedList` 型のパラメータに文字列を渡したとき（ネストスタックの出力 `!Join [",", [!Ref A, !Ref B]]` を受けるなど）は、`$concat` の文字列の部分を区切り文字の位置で分け、印は分けずにリストにする（`{"$concat": [A の印, ",", B の印]}` → `[A の印, B の印]`）。
- ネストスタックの出力（`!GetAtt NetworkStack.Outputs.VpcId`）と、子テンプレートの `Parameters` に渡した値は、たどって元のリソースへの `$res` にする（TF のモジュールの出力・変数も同じ）。たどった経路は 7.3 の `through` に書く。`AWS::CloudFormation::Stack` のリソース自身の `props` の `Parameters` は、リストの分割をしない（分割は子テンプレートの側で、パラメータの型を見て行う）。
- TF のスプラット（`aws_subnet.private[*].id`）は、インスタンスの数が決まればインスタンスごとの `$res` のリストにし、決まらなければ `{"$res": "aws_subnet.private[*]", "attr": "id"}` の1つにする。count・for_each の無いリソースのスプラットは、要素1つのリストにする（Terraform と同じ）。
- **TF の props:** 属性とブロック。ブロックは同じ名前のものをリストにする（plan JSON と同じ形。`load_balancer[0].target_group_arn`）。メタ引数（`count`、`for_each`、`provider`、`depends_on`、`lifecycle`、`provisioner`、`connection`。module は `source`、`version`、`providers` も）は props に入れない。値が `null` の属性は書かない（Terraform では書かないのと同じ）。count・for_each の値が決まらないブロック（×N）は `enabled: null`（0 個かもしれないため）。
- **TF の `$res` の `attr`:** address の後ろの最初の属性名（`aws_eks_cluster.x.certificate_authority[0].data` → `certificate_authority`）。属性の無い参照（`aws_lb_listener.http`）は `null`。インスタンスのキー（`[0]`、`["ssm"]`）は address の側に入れる（決まらなければ `[*]`）。展開したモジュールの出力への参照は、出力の値をたどった先のリソースと属性（`module.alb.target_groups["app"].arn` は、出力 `target_groups` が `aws_lb_target_group.this` なので `{"$res": "module.alb.aws_lb_target_group.this[\"app\"]", "attr": "arn"}`）。黒箱のモジュールの出力への参照は `{"$res": "module.x", "attr": "<出力の名前>"}`（2章）。`terraform_remote_state` の出力への参照は `{"$res": "data.terraform_remote_state.x", "attr": "outputs.<出力の名前>"}`（下の「TF のモジュール」）。
- **TF の擬似パラメータと AZ:** 引数の無い（`provider` も無い）`data.aws_region`（`name`・`region`・`id`）、`data.aws_caller_identity`（`account_id`）、`data.aws_partition`（`partition`・`id` → `AWS::Partition`、`dns_suffix` → `AWS::URLSuffix`）は `$pseudo`。ほかの属性（`data.aws_caller_identity.x.arn` など）と、引数のある data（別のリージョンを指す `data.aws_region` など）は `$res`。引数が `provider` 以外だけの `data.aws_availability_zones` の `names[<番号>]` は `$az`（番号）、`names` 全体は `{"$az": "*"}`。`$pseudo`・`$az` にした参照は、CFN の擬似パラメータ・`Fn::GetAZs` と同じく `references` に出さない。
- **TF のモジュール（手順3）:** module の呼び出しは、source で読み方を決める。
  - **ローカルモジュール**（`./`・`../` で始まる source。ルートの外の `../../` も）は、フォルダの `.tf` を読んで再帰的に展開する。中のリソースの address は呼び出しのインスタンスの address を前に付ける（`module.app.aws_ecs_service.this`、count・for_each の呼び出しは `module.m[0].…`・`module.m["k"].…`、入れ子は `module.db.module.db_instance.…`）。`module` フィールドはその前の部分（`module.app`、`module.m[0]`）。呼び出しそのものは `resources` に載せない。`path.module` はそのモジュールのフォルダ（`root` からの相対パス）。
  - **変数と出力:** 子の変数の値は、呼び出しの引数を親の中で評価した値（count・for_each の呼び出しは `count.index`・`each.*` も親の側）。`type` の変換、`default`、`nullable = false`（`null` を渡したら `default`）、`sensitive`・`ephemeral`（値を使わない）はルートの変数と同じ。引数が無く `default` も無い変数は `$unknown`（`TF-UNRESOLVED-VAR`）、子に宣言の無い引数は `TF-VAR-UNDECLARED`。親から `module.x.y` を参照すると、子の出力 `y` の値を子の中で評価する。`sensitive`・`ephemeral` の出力の値は使わず `$unknown`（`TF-SENSITIVE-VAR`、info。中の参照は `unevaluated` で残す）。たどった経路は参照の `through` に、`from` の側から順に入れる（子のリソースが親のリソースを指すときは `module.app.var.vpc_id`、親が子のリソースを指すときは `module.net.output.vpc_id`、両方をまたぐときは `["module.app.var.environment", "module.db.output.db_instance_address", "module.db.module.db_instance.output.db_instance_address"]`）。`module.x` そのもの（属性を付けない参照）は、出力の名前をキーにしたオブジェクト。
  - **count・for_each の呼び出し:** インスタンスごとに展開する。count が 0・for_each が空の呼び出しの中のリソースは、添字なしの address（`module.z.aws_sqs_queue.q`）で `enabled: false`（ネストスタックの子と同じく、中のリソースは呼び出しの `enabled` との弱い方）。決まらない呼び出しは `module.n[*].…` で、中のリソースはすべて `enabled: null`・`multiplicity: "N"`（診断 `TF-COUNT-UNRESOLVED` は呼び出しの address `module.n[*]` に1つ）。
  - **depends_on:** 呼び出しの `depends_on` は、中のすべてのリソースの `depends_on` の参照になる。`depends_on = [module.x]` の先は、展開したモジュールなら中のすべてのリソース（入れ子を含む）、黒箱なら呼び出し。
  - **循環と深さ:** 呼び出しの経路にすでにあるフォルダ（要約表）を呼ぶものは黒箱（`TF-MODULE-CYCLE`、warn）。入れ子が 16 段を超える呼び出しも黒箱（`TF-MODULE-DEPTH`、warn）。フォルダが無い・`.tf` が無いローカルモジュールは黒箱（`TF-MODULE-UNREADABLE`、warn）。
  - **レジストリモジュール**は、A5 の要約表（[data/module-summaries/](../../../skills/aws-iac-diagram/data/module-summaries/)。vpc 6.x、alb 10.x、rds 7.x、eks 21.x）に source と版が合えば、要約表の HCL を同じように評価して展開する（`via: "module_summary"`、4章。版の選び方は docs/spec/module-summaries.md の 2章。版の指定が無い・上限が無いときは前提に書く）。呼び出しに1つ `TF-MODULE-SUMMARY`（info）を書く。要約表に写していないリソースを作る入力を渡したら `TF-MODULE-SUMMARY-INPUT`（info。入れ子の入力 `listeners.*.authenticate_cognito` なども、渡した値のその位置に `null`・空の `{}`・`[]` 以外の値があれば書く。途中の値が決まらず調べられなかった経路は、同じ code の info（`path` が `unknown`）に別に書く）、要約表に無い出力の参照は `$unknown`（`TF-MODULE-SUMMARY-OUTPUT`、warn）。要約表に無い・版が合わないもの、`git::`・`github.com/`・`s3::`・URL などのリモートのソースは黒箱（`TF-MODULE-BLACKBOX`、info。理由を message に書く。IAM だけのモジュールはそのことも書く）。黒箱の呼び出しのうち、source が `terraform-aws-modules/` のもの（要約表の中の呼び出しを含む）は、`create` 引数（このモジュール群の慣習で、false なら何も作らない）が false と決まれば `enabled: false`、決まらなければ `enabled: null`（count が決まらないときと同じ）にし、どちらも `TF-MODULE-NOT-CREATED`（info）を書く。ほかの source の `create` は、意味が分からないので読まない。要約表の中の黒箱の呼び出しも、count が 0 のリソースと違って載せる（参照の先を残すため）。ネットワークからモジュールを取りに行かない（`.terraform/modules` も読まない）。
  - **provider:** モジュールの中のリソースの provider は、メタ引数 `provider`（無ければ型の先頭、`aws_vpc` → `aws`）の名前を、呼び出しの `providers` 引数（`{ aws = aws.use1, aws.east = aws.use1 }`）でたどり、設定（`provider` ブロック）のあるモジュールの名前にする。`providers` 引数の無い呼び出しは、既定の（alias の無い）provider を呼び出し側から引き継ぐ（Terraform と同じ）。たどった先が alias の provider なら `provider`（`aws.use1`。設定のあるモジュールの中の名前）と、その設定の `region` を書く。ルートの既定の provider なら書かない。設定まで届かない alias（`configuration_aliases` を渡していない）は `provider` だけ書き、`TF-PROVIDER-UNCONFIGURED`（info）。リソースの引数 `region`（AWS provider v6。vpc モジュールなどの `region = var.region`）があればそれが優先する。黒箱の呼び出しは、`providers` 引数の `aws` が alias の provider なら、その `provider` と `region` を呼び出しに書く。
  - **`terraform_remote_state`:** 別の構成の state は読まない（手元に無く、秘密の値が入りうるため）。data として `resources` に載せ（type `terraform_remote_state`。正規化は `H-DATA`）、`data.terraform_remote_state.x.outputs.vpc_id`（`outputs["vpc_id"]` も）への参照は `{"$res": "data.terraform_remote_state.x", "attr": "outputs.vpc_id"}`（CFN のスタックの `Outputs.<名前>` と同じ形）。出力の名前の無い参照（`outputs` そのもの）は `attr: "outputs"`。
  - **作られないブロックと `try`:** count が 0 のブロックの添字（`aws_x.y[0]`）は、ふだんは作られないブロックへの参照（上の「count・for_each」）だが、`try()`・`can()` の中では Terraform と同じく誤りにして次の式に進む（モジュールの `try(aws_vpc_ipv4_cidr_block_association.this[0].vpc_id, aws_vpc.this[0].id, "")` が `aws_vpc.this[0]` になるように）。locals・子の変数・子の出力は、使った位置によらず1回だけ（`try` の外として）評価してキャッシュするので、`try(local.x, "")` の `local.x` の中の count が 0 のブロックの添字は、作られないブロックへの参照のまま（Terraform ではその local 自体が誤りになる、正しくない設定のときだけ起きる。制約）。
  - **AZ の名前に当てる関数:** `regexall()` の文字列が `$az`（AZ 名 1 つ）のときは、形の違う AZ 名の代表（`us-east-1a`・`ap-northeast-1c`・`eu-central-1b`・`cn-north-1a`・`us-gov-west-1a`・`il-central-1a` など。`scripts/aws_iac_diagram/adapters/terraform/evaluator/functions.py` の `AZ_NAME_SAMPLES`）のすべてでマッチの数が同じときだけ、その数に決める（代表によって違えば `$unknown`。vpc モジュールの `length(regexall("^[a-z]+-", element(var.azs, count.index))) > 0` で、AZ 名か AZ ID かを見分けるため。マッチした文字列は `$unknown`）。`lookup()` の空のマップは、キーが決まらなくても既定値を返す。
  - **`null` との比較:** `==`・`!=` の片方が `null` で、もう片方が `null` になりえない値（マップ・リスト・テンプレートの `$concat`・`$json`・`$pseudo`・`$az`、属性の無いリソース・モジュールの呼び出しそのもの `aws_x.y`・`module.x`）なら、中に決まらない値があっても結果を決める（モジュールの `for_each = var.rules != null ? var.rules : {}` に、リソースの属性を含むマップを渡したとき）。リソースの属性（`$res`）と `$unknown` は `null` かもしれないので決めない。
- **TF の plan JSON（手順4）:** `terraform show -json <plan のファイル>` の出力（`format_version` 1.x）を読む（`scripts/aws_iac_diagram/adapters/terraform/plan/`）。入力の渡し方は2つ。読み込みは、256 MiB までの JSON で、`NaN`・`Infinity`・深すぎる入れ子・読む入れ物の型の違い（`resource_changes` が文字列、`address` が無い・空、`type` が空、など）は終了コード 2（`unexpected structure at <JSON のパス>` の形。値と絶対パスは書かない）。
  - **plan JSON だけ**（`--input <plan JSON>`。`.json` のファイルで、`format_version`・`terraform_version` と `planned_values` か `resource_changes` があれば plan JSON とみなす。state の JSON・ほかの JSON は終了コード 2）。`root` は plan JSON のパス（`--root-base` からの相対パス。別のドライブにあって相対パスにできなければ、.tf と合わせるときと同じくファイルかフォルダの名前だけを書き、`TF-ROOT-OTHER-DRIVE`（info）を出す。絶対パスは書かない）、`file` はすべて plan JSON のファイル名（plan JSON は .tf のファイル名と行を持たない）。`--var-file`・`--var`・`--redact-var` は使えない（変数の値は plan のもの）。
  - **.tf と plan JSON**（`--input <フォルダ> --plan <plan JSON>`。plan JSON があれば優先する、の推奨の形）。.tf を読む前に、plan の `variables`（Terraform が使った値）を変数の値として渡す（出どころは `"plan"`。`--var-file`・`--var` はその後に重なる）。`root`・`file`・`props`・参照の位置・`through`・`pruned` は .tf のもの、address と `enabled` は plan のもの（下の「合わせ方」）。
  - **address と enabled:** インスタンスは `resource_changes`（`actions` が `["delete"]`・`["forget"]` だけのものは除く。その address は `prior_state` からも足さない。置き換えで残った古いオブジェクト `deposed` も数えない）、`prior_state`（plan のときに読んだ data）、`planned_values` から取る（count・for_each・モジュールの呼び出しの展開は Terraform の結果のまま。`[*]`・×N にならない）。`configuration` にあってインスタンスの無いブロックは、添字なしの address で `enabled: false`（.tf と同じ。count が 0 の呼び出しの中も添字なし）。**レジストリ・git などリモートのモジュール（とその中のモジュール）の中では、作られないブロックと `data` を載せない**（要約表から展開するときと同じ。4章の `module_summary`）。plan JSON の中身は Terraform が読んだ本物のモジュールなので、`via` は付けない（`module_summary`・`module_blackbox` にならない。.tf と合わせたときは .tf のリソースの `via` が残る）。`module`・`provider`（`provider_config_key` の alias）・`region`（alias か、モジュールの中で設定した provider のリソースは plan の値の `region`（AWS provider v6）か provider の設定の `region`。既定の provider のリソースは、引数 `region` を定数で書いたときと、値が既定のリージョンと違うときだけ）は .tf と同じ形。
  - **props:** `configuration` の `expressions` にある属性とブロック（書かれたものだけ。provider が埋める既定値は書かない）。値は plan の `after`（data は `prior_state` の `values`）。`after_unknown` の位置は `{"$unknown": "known after apply (terraform plan)"}`（診断 `TF-PLAN-UNKNOWN`、info）。**`after_sensitive`（`sensitive_values`）の位置の値は使わない**（`{"$unknown": "sensitive value in the plan; not used"}`、`TF-PLAN-SENSITIVE`、info。plan JSON の `variables` と `configuration` には sensitive の変数の値が平文で入るが、IR には書かない。2026-10-17 のユーザーの決定と同じ）。作られないブロックは `constant_value` だけ。`configuration` に無い入れ子のブロック（dynamic ブロック。plan JSON の `configuration` に出ない）は値だけ入れ、`TF-PLAN-DYNAMIC-BLOCK`（info）を書く。値が `null` の属性は書かず、JSON の文字列は `$json`（.tf と同じ規則）。plan だけのときは、引数の無い `data.aws_caller_identity` などの値も plan の値（`$pseudo`・`$az` にならない。参照も出さないのは .tf と同じ）。
  - **参照:** 7.3 の「plan JSON の参照」。`local.*` は plan JSON に式が無いのでたどれない（使ったものの数を1つの `TF-PLAN-LOCALS`（info）にまとめる）。`depends_on`（呼び出しの `depends_on` は中のすべてのリソースへ）は .tf と同じ。
  - **合わせ方（.tf と plan JSON）:** plan の address の一覧を正とする。.tf に同じ address・同じ型のリソースがあれば、.tf のもの（`file`・`props`・`via`・`provider`・`region`）を使い、`enabled` を plan に合わせ、.tf の `props` の `$unknown` のうち、値が決まらないことによる診断（`TF-UNRESOLVED-VAR`・`TF-UNEVALUATED`・`TF-EVAL-ERROR`・`TF-UNSUPPORTED-FUNCTION`・`TF-COUNT-INDEX`・`TF-MODULE-SUMMARY-OUTPUT`・`TF-UNDEFINED-REF`）のある位置を、plan の値が決まっていて sensitive でなければその値で埋め、その診断を消す（`file()` の値など。秘密の値 `TF-SENSITIVE-VAR`・`--redact-var` の位置は埋めない。JSON の文字列の全体が sensitive か known after apply のときは、中の位置も埋めない）。**plan が sensitive とした位置（`after_sensitive`）は、.tf の値も使わない。** .tf の評価は plan の `variables` の値を使うので、`sensitive = true` と宣言していない変数が provider の sensitive の属性（`password`・`secret_string` など）に入ると、.tf の値に秘密が残る。.tf の `props` を plan の印に合わせてたどり、印のある位置を `{"$unknown": "sensitive value in the plan; not used"}` にして `TF-PLAN-SENSITIVE`（info）を出す（`$json`・`$concat` は値の全体として扱う。値を持たない `$res`・`$pseudo`・`$az` はそのまま。**`$unknown` も伏せる**: 理由の文に評価の誤り（`lookup(): no key '<値>'` など）で値が入りうるため。印と値の形が合わないときと、ブロックの数が違うときは、その全体を伏せる）。伏せた位置の下にある .tf の診断（`TF-EVAL-ERROR` など。文に値が入りうる）は消す（`TF-PLAN-SENSITIVE` を1つ出す）。**sensitive の印は、`resource_changes` の `after_sensitive`・`before_sensitive`、`prior_state` と `planned_values` の `sensitive_values` を位置ごとに OR で合わせて使う**（どれか1つが true にした位置は伏せる。`after_sensitive` が `true` のときはすべての属性）。**作られないリソース**（count が 0、`terraform plan -destroy` で消えるもの）は、plan に `after` も、count 0 では sensitive の印も無く、変数の値が sensitive かを確かめられない。.tf の値のうち、plan の `configuration` の定数と同じもの（リテラル）と `$res`・`$pseudo`・`$az` だけを残し、ほかは `{"$unknown": "not created; only literal values are kept (not values from plan variables)"}` にして `TF-PLAN-LITERAL-ONLY`（info）を出す（消す前の `before_sensitive`・`prior_state` の印の位置は sensitive の理由で伏せる。plan だけのときも、その印で `configuration` の定数を伏せる）。.tf に無いリソース（.tf の ×N の `[*]`・黒箱の呼び出しの中身・要約表に無いリソース・`.tf.json` のブロック）は plan から作ったものを使い、`file` は `.tf.json` のファイル、同じブロックの .tf のファイル、モジュール（無ければ外側の呼び出し）の .tf のファイルの順に決める。plan に無い .tf のリソースは書かず、件数を `TF-PLAN-NOT-PLANNED`（info）に書く。参照は .tf のもの（先が plan に無い `[*]` はインスタンスごとに展開して `unevaluated`、展開できないものは消し、`props` のその `$res` は `$unknown`）に、plan の `configuration` にあって .tf の参照に無い組（`from` と先のブロック）を `unevaluated` で足す（`TF-PLAN-EXTRA-REF`、info。`configuration` の参照を優先する、の実装）。自作 fixture の5構成では、合わせた結果の `resources`・`references` は .tf だけの結果と同じになる。
  - plan が失敗していたら（`errored: true`）`TF-PLAN-ERRORED`、完全でなければ（`complete: false`、`deferred_changes`）`TF-PLAN-INCOMPLETE`（どちらも warn）。`terraform plan -destroy`（managed のリソースの変更がすべて delete・forget）なら `TF-PLAN-DESTROY`（warn。設定に残るブロックは `enabled: false`）、一部が消えるだけなら同じ `code` を info で出す。.tf と合わせるとき、plan と .tf のブロック（添字なし。.tf の黒箱のモジュールの中は数えない）の食い違いが3割を超えたら、フォルダが合っていないとして `TF-PLAN-MISMATCH`（warn）を出す。plan の `source` が指すローカルモジュールのフォルダが `--input` のフォルダの外にあるときは、その `.tf.json` を探さず `TF-PLAN-PATH-OUTSIDE`（info）を出す。`evaluation.assumptions` に plan JSON から読んだこと（terraform と format の版。英数字と `.+_-` だけ、32 文字まで）を書く。
- **TF の作られないブロックの診断:** count が 0 などで作られないブロック（`enabled: false`）の props の中で、値が決まらないことによる診断（`TF-UNRESOLVED-VAR`・`TF-EVAL-ERROR`・`TF-UNEVALUATED`・`TF-UNSUPPORTED-FUNCTION`）は info にする（Terraform もそのブロックを評価しないので、図に影響しない）。参照の誤り（`TF-UNDEFINED-REF`）と循環（`TF-CYCLE`）は warn のまま（設定の誤りなので）。
- **TF の変数のファイルの名前:** `evaluation.var_files` は `root` からの相対パス。別のドライブにあって相対パスにできなければファイル名だけを書き、`TF-VARFILE-OTHER-DRIVE`（info）を出す（絶対パスにはユーザー名などが入るため）。読めない変数のファイルの誤りの文には、位置（行・列）だけを書き、値を書かない。
- **TF のそのほかの値:** `path.module`・`path.root`・`path.cwd` は `root` からの相対パス（ルートモジュールは `"."`。モジュールの中の `path.module` はそのモジュールのフォルダ）。`terraform.workspace` は `"default"` とし、使ったときに `evaluation.assumptions` に書く（アダプタの `--workspace <名前>` で別のワークスペースにでき、そのときは `terraform.workspace is evaluated as "<名前>" (--workspace)` と書く。plan JSON だけのときは使えない）。`jsonencode(...)` は `$json`（中身が `$unknown` になったときは、その `$unknown`。`jsonencode("x")` のように中身が文字列・数などのスカラーの `$json` もある）。`"${…}"` と heredoc はテンプレートとして `$concat` にし（`${…}` が1つだけの文字列は、その値のまま。HCL と同じ）、JSON として読めれば `$json` にする（CFN と同じ規則）。`file()`・`templatefile()`・`filemd5()` などファイルを読む関数は、ファイルを読まずに `$unknown`（診断 `TF-UNEVALUATED`）にし、引数の中の参照（`templatefile` の変数に渡したリソースなど）は `unevaluated` で残す。
- **SAM:** `Globals` は各リソースに混ぜてから `props` にする（cfn-lint と同じ。マップは中まで、リストは Globals の後ろにつなぐ、値はリソースの方。組み込み関数は1つの値として扱い、中に混ぜない）。暗黙の API（`implicit`）にも `Globals.Api`／`Globals.HttpApi` を混ぜる。暗黙の API は、`AWS::Serverless::Function` と `AWS::Serverless::StateMachine` の `Events` から作る。`Events`、`Policies`（ポリシーテンプレート）はプロパティのまま `props` に残し、SAM の変換（Transform）はしない（変換に当たることは、正規化の規則で扱う。relation-resources.md）。

### 7.3 参照

```json
{"from": "AppService", "path": "Properties.LoadBalancers[0].TargetGroupArn", "to": "AppTargetGroup", "attr": null, "fn": "Ref", "state": "active"}
```

| フィールド | 必須 | 内容 |
|---|---|---|
| `from`, `to` | ○ | リソースの address。`to` は入力の中のリソースだけ（`$import` などの解決できないものは参照にしない） |
| `path` | ○ | `from` のどこから参照したか。**評価した後の `props` の上の位置**で、印の中（`$concat` の何番目か）は含めない。CFN は `Properties.…`（`DependsOn` は `DependsOn`。`Properties` の外の `Metadata`、`CreationPolicy`、`UpdatePolicy` の中の参照も出し、`Metadata.…` のように書く。cfn-lint はこれらも辺にするため）、TF は属性のパス（`load_balancer[0].target_group_arn`、`depends_on`）。リストの位置は `[0]`、識別子（`[A-Za-z_][A-Za-z0-9_-]*`）として書けないキー（`.` や空白を含むなど）は `["key"]`、`$$` で逃がしたキーは元のキーで書く。`$json` は位置に数えず、中の位置をそのまま続ける。同じ `$concat` の中に同じ参照（`to`・`attr` が同じ）が2回あっても1件。`state` が `pruned`／`unevaluated` の参照は、その参照を含んでいたプロパティの位置 |
| `attr` | ○ | 参照した属性（CFN の `Ref` は `null`） |
| `fn` | ○ | CFN: `Ref`／`GetAtt`／`Sub`（`${X}` は `attr: null`、`${X.Attr}` は `attr` に属性名）／`ImportValue`（入力の中で解決できたもの）／`DependsOn`。TF: `ref`／`depends_on` |
| `state` | ○ | `active`（評価した後の `props` にある）／`pruned`（`Fn::If` の選ばれなかった側にあった。TF は 7.2 の A4 の後ろの段落）／`unevaluated`（評価できなかった値の中にあった。`$unknown` になったところ） |
| `through` | | たどった経路を、`from` の側から順に並べる。CFN: `NetworkStack.Outputs.VpcId`、`AlbStack.Parameters.PublicSubnetIds`、`Export:<エクスポート名>`。TF: `module.network.output.vpc_id`、`module.app.var.subnet_ids` |

- **一意のキーと並び順:** `(from, path, to, attr, fn)` で1件に決まり、この順で並べる（`!Sub "${Bucket}/${Bucket.Arn}"` のように、同じ位置から同じリソースへ別の属性で参照するものは別の件になる）。
- **`props` との対応:** `props` の中のすべての `$res` は、`state: "active"` の参照に1件ずつ対応する（`from`、`path`、`to`、`attr` が同じ）。逆に、`references` にあって `props` に無いのは、`DependsOn`／`depends_on`、CFN の `Properties` の外（`Metadata` など）の参照、`state` が `pruned`・`unevaluated` のものだけ。
- `AWS::CloudFormation::Stack` のリソース自身も、`Parameters` に渡した値の参照を出す（`from` はスタックの論理ID）。子テンプレートの中の参照は、子のリソースを `from` にして別に出す。
- ネストスタックの出力をたどった値に参照が残らないとき（出力が文字列だった、評価できなかった）は、スタックのリソースへの参照（`to` はスタック、`attr` は `Outputs.<名前>`、`state: "unevaluated"`）を残す。出力の中にあった `pruned`／`unevaluated` の参照も、使った側の参照として、`through` に出力を足して残す（cfn-lint は使った側 → スタックを辺にするため）。
- 同じ子テンプレートを2つのスタックから使うときは、スタックごとに別々に読み、address の先頭（親の論理ID）で区別する。
- `AWS::NoValue` でリストの要素が消えると、後ろの要素の位置（`[n]`）がずれる。C1 の照合では、この位置のずれを考えて対応づける（CRITERIA の 1.6）。
- **plan JSON の参照（TF。フェーズ2 の手順4）:** plan JSON の `configuration` は、属性ごとに式の中の参照の一覧（`references`）だけを持ち、式の形を持たない。次の順で参照にする。
  1. **重なりをまとめる:** `references` は同じ参照を細かさの違う文字列で重ねて出す（`aws_subnet.private[0].id`・`aws_subnet.private[0]`・`aws_subnet.private`、`module.alb.target_groups["app"].arn`・…・`module.alb`）。ほかの文字列の前の部分（後ろに `.` か `[` が続く）になっている文字列を除き、最も細かいもの1つにする（`aws_subnet.private[0].id`）。`aws_x.a` と `aws_x.ab` のように前の部分でないものは両方残す。
  2. **先を決める:** 添字があればそのインスタンス（`to`、`attr` はその後ろの最初の属性名）。添字が無く、先のブロックに count・for_each があれば、すべてのインスタンス（スプラット `aws_subnet.public[*].id` は `configuration` では `aws_subnet.public` だけになるので、`attr` は `null`）。作られないブロックは添字なしの address。`var.<名前>`（モジュールの変数）は呼び出しの式の参照へ、`module.<名前>.<出力>` は子の出力の式の参照へたどり（後ろの `["app"].arn` は出力の先に続ける）、`through` に `module.x.var.y`・`module.x.output.y` を足す（.tf と同じ形）。`$pseudo`・`$az` に当たる data の属性（7.2）とリモートのモジュールの中の `data` は参照にしない。`local.*`・`count.*`・`each.*`・`path.*`・`self.*` はたどらない。
  3. **props に置くか:** 属性の値（plan の値）と先のリソースの値で決める。値の全体が known after apply で、先が1つのインスタンスなら、その位置を `$res` にして `active`（式の形が分からないので、`"${aws_s3_bucket.x.arn}/*"` や `jsonencode` の中の参照1つも、値の全体への `$res` になる。正確な位置は .tf と合わせると出る）。先がスプラット（すべてのインスタンス）なら、インスタンスごとの `$res` のリストにする。値の中の known after apply の位置の数と先の数が同じなら、順に `$res` にする。値が決まっていて、先のリソースの属性の値（決まっていて sensitive でないもの）と同じなら `$res`、文字列の一部なら `$concat` にして `active`。値が `null`（属性が無い）なら `pruned`（条件で選ばれなかった）。それ以外（count.index・each.* で選ぶ参照は、添字が分からないのですべてのインスタンスへ）は `unevaluated`。
  4. この規則は推測を含むので、plan JSON だけの参照は .tf の参照と `state`・`attr`・`path` が違いうる（`from` と `to` の組は、locals・dynamic ブロック・`each.value` を通したものを除いて同じ。`tests/integration/terraform/test_plan_fixtures.py`）。.tf と plan JSON を合わせたときは .tf の参照を使う（7.2 の「TF の plan JSON」）。

### 7.4 入力ごとの扱い（公開サンプルで見つかった問題。SELECTION.md の 4）

| 問題 | 扱い |
|---|---|
| CFN の `TemplateURL` が S3 の URL（C04、C05） | URL のパスと、`root` のディレクトリの下のファイルの相対パスを、末尾から `/` 区切りの要素ごとに比べ、一致する要素が最も多いファイルを子テンプレートとして読む（`infrastructure/vpc.yaml` と `vpc.yaml` があり、URL が `…/infrastructure/vpc.yaml` なら前者）。最も多いものが2つ以上あるか、1要素も一致しないときは黒箱のモジュール（2章）にし、`diagnostics` に書く。読み替えたことは `evaluation.assumptions` に書く |
| TF のローカルモジュールがルートの外（T04、T14、T15 の `../../`） | そのまま読む。`file` は `../` 付きの相対パス（4章） |
| AWS 以外のプロバイダの型（T15 の awscc、T18 の kubernetes、T09 の opensearch など） | アダプタはそのまま `resources` に載せる。扱いは正規化の規則表（resource-catalog.md）で決める。方針: awscc の型は同じ名前の CFN の型（`awscc_ec2_vpc` → `AWS::EC2::VPC`）として扱う。random、null、time などクラウド上の実体が無いものは既存の `H-UTILITY`。それ以外のプロバイダ（kubernetes、helm、tls、local など）は非表示（規則 `H-NONAWS`）。opensearch の index のように AWS のリソースの中身を作る型は、そのリソースに統合する（既存の `M-AOSS-INDEX`）。個々の型の行は、フェーズ3 で公開サンプルの型を足すときに書く |
| 既存のインフラを指す TF の `data`（T20 は 413 件） | `data` も `resources` に載せる（address は `data.` 付き）。描くか非表示にするかは正規化で決める。方針: 描く型の `data`（`data.aws_vpc`、`data.aws_subnet` など）が、描くリソースから参照されていれば、既存のノードとして描く。それ以外は `H-DATA`。`terraform_remote_state` は state を読まずに data として載せ、出力への参照は `attr: "outputs.<名前>"`（7.2。フェーズ2 の手順3 で決めた）。正規化では `H-DATA` |
| python-hcl2 が heredoc の終端の空白で読めない（T06） | TF アダプタで、heredoc の開始（`<<EOF`）と終端の行の末尾の空白を取ってから読む（開始の行の後ろの空白でも読めないため）。取ったことを `diagnostics`（level `info`、`TF-HEREDOC-TRAILING-SPACE`）に書く |

### 7.5 診断

```json
{"level": "warn", "code": "CFN-UNRESOLVED-PARAM", "address": "Bastion", "path": "Properties.KeyName", "message": "parameter KeyName has no value"}
```

- `level` は `info`（読み替えなど、結果に影響しない）／`warn`（評価できなかった値があり、図が不完全になりうる）／`error`（そのリソースか、ファイルを読めなかった）。
- `code` は大文字で、raw では `CFN-…`／`TF-…`。正規化後の IR にも同じ形の `diagnostics` を持たせ、そこでは `NORM-…`（「使わなかった参照」、「条件が決まらない」など。edge-rules.md）。一覧は各段階の実装と一緒に決める。
- **診断コードの一覧の正は `scripts/aws_iac_diagram/core/diagnostics.py`**（コードごとの level と短い説明。アダプタのコードにある `TF-…`・`CFN-…` の文字列がそこに無いと、そこにあって使われていないと、`tests/architecture/test_diagnostics_registry.py` が落ちる。この章の一覧と同じであることは `tests/architecture/test_diagnostics.py` が確かめる）。コードを足す・level を変えるときは、両方と `tests/golden/`（出力が変わるとき）を同じコミットで直す。同じコードが場所によって level を変えるものがある（下の「warn／info」などの書き方）。
- TF アダプタの `code` の一覧（43 個。CFN と同じく「`コード`（level。説明）」の形。level は `diagnostics.py` と同じであることをテストが確かめる）:
  - 読み込み: `TF-PARSE-ERROR`（error。.tf を読めない（ほかのファイルは読む））、`TF-HEREDOC-TRAILING-SPACE`（info。heredoc の開始・終端の行の末尾の空白を取ってから読んだ（python-hcl2 が読めないため））、`TF-DUPLICATE-BLOCK`（warn。同じ名前の変数・local・output・リソースが複数ある。最初のものを使う）、`TF-MALFORMED-BLOCK`（warn。ブロックの形が誤り（provider の指定、providers、dynamic ブロック、モジュールの source など））、`TF-OVERRIDE-UNMATCHED`（warn。*_override.tf のブロックに対応する元のブロックが無い）、`TF-TFJSON-UNSUPPORTED`（warn／info。.tf.json は .tf だけでは読まない（warn）。plan JSON と一緒のときは plan から取る（info））、`TF-ROOT-OTHER-DRIVE`（info。root が別のドライブにあり、ファイル名・フォルダ名だけを書いた（Windows））、`TF-VARFILE-OTHER-DRIVE`（info。変数のファイルが別のドライブにあり、相対パスにできないので名前だけを書いた（Windows））。
  - 変数と評価: `TF-UNRESOLVED-VAR`（warn／info。値の無い変数。使ったところごと。作られないリソースの中なら info）、`TF-UNRESOLVED-VARS`（info。値の無い変数と *.tfvars の候補のまとめ）、`TF-SENSITIVE-VAR`（info。sensitive の変数・出力の値は使わない）、`TF-VAR-UNDECLARED`（warn。宣言の無い変数に値を渡した（--var、--var-file、--redact-var、モジュールの引数））、`TF-VAR-INVALID`（warn。変数の値が定数でない・式として誤り（--var、tfvars、default））、`TF-UNEVALUATED`（warn／info。決まらない値を含む演算・関数、ファイルを読む関数など（warn）。self・要約表の path.module など図に影響しないものは info）、`TF-UNSUPPORTED-FUNCTION`（warn／info。未対応の関数。作られないリソースの中なら info）、`TF-EVAL-ERROR`（warn／info。Terraform なら誤りになる式（count が null・負、for_each の型の誤りなど）。作られないリソースの中なら info）、`TF-UNDEFINED-REF`（warn。定義の無い変数・local・出力・リソースへの参照、depends_on の宛先が無い）、`TF-CYCLE`（warn。変数・local・output が自分自身を参照している（値は決まらない））、`TF-EPHEMERAL`（info。ephemeral の値。apply の前は決まらない）。
  - count・for_each: `TF-COUNT-UNRESOLVED`（warn。count・for_each が決まらない。×N（enabled: null）で出す）、`TF-COUNT-INDEX`（info。×N のリソースや、作られないブロックの中の count.index・each.*。値は決まらない）。
  - モジュールとプロバイダ（7.2 の「TF のモジュール」。モジュールの呼び出しの診断の `address` は呼び出しのインスタンスの address で、リソースではない）: `TF-MODULE-BLACKBOX`（info。モジュールを読まず、黒箱にした（レジストリの要約表に無い、source を読めないなど））、`TF-MODULE-SUMMARY`（info。要約表（A5）でモジュールを展開した。主要なリソースだけを書いている）、`TF-MODULE-SUMMARY-INPUT`（info。要約表が扱わないモジュールの入力を渡している（その入力が作るリソースは書かない））、`TF-MODULE-NOT-CREATED`（info。count が 0 などで作られないモジュールの呼び出し（インスタンスが無い））、`TF-MODULE-UNREADABLE`（warn。ローカルモジュールのフォルダを読めない。黒箱にする）、`TF-MODULE-CYCLE`（warn。ローカルモジュールが自分自身を呼んでいる。黒箱にする）、`TF-MODULE-DEPTH`（warn。モジュールの入れ子が深すぎる。黒箱にする）、`TF-MODULE-SUMMARY-OUTPUT`（warn。要約表に無いモジュールの出力を参照している）、`TF-MODULE-SUMMARY-TABLE-MISSING`（warn。要約表 data/module-summaries/ が無い・読めない（vpc・alb・rds・eks のモジュールのフォルダごと無いときを含む）のにレジストリモジュールの呼び出しがある）、`TF-PROVIDER-UNCONFIGURED`（info。alias の provider の設定がモジュールにも呼び出し元にも無く、region を決められない）。
  - plan JSON（7.2 の「TF の plan JSON」）: `TF-PLAN-UNKNOWN`（info。plan で apply の後にしか決まらない値）、`TF-PLAN-SENSITIVE`（info。plan で sensitive の値。値は使わない）、`TF-PLAN-DYNAMIC-BLOCK`（info。plan の configuration に無いブロック（dynamic ブロック、provider が埋めるブロック）。中の参照は plan JSON からは分からない）、`TF-PLAN-LOCALS`（info。plan JSON には local の式が無く、local を通した参照は分からない（.tf のフォルダと一緒に読むと分かる））、`TF-PLAN-NOT-PLANNED`（info。.tf にあって plan に無いリソースを出力しなかった）、`TF-PLAN-EXTRA-REF`（info。plan の configuration にあって .tf から見つからない参照を、unevaluated で足した）、`TF-PLAN-PATH-OUTSIDE`（info。ローカルモジュールのフォルダが --input の外にあり、その .tf.json は探さない）、`TF-PLAN-LITERAL-ONLY`（info。作られないリソースの、リテラル以外の値を plan から取らなかった）、`TF-PLAN-ERRORED`（warn。plan が失敗している（errored: true）。plan は途中までかもしれない）、`TF-PLAN-INCOMPLETE`（warn。plan が不完全（incomplete・deferred_changes））、`TF-PLAN-MISMATCH`（warn。plan と .tf のフォルダが食い違う（おそらく別の構成））、`TF-PLAN-DESTROY`（warn／info。destroy の plan（すべてが削除）は warn。一部だけ消える・state から外れる plan は info）。
- CFN アダプタの `code` の一覧（19 個。TF と同じく、`diagnostics.py` と同じであることをテストが確かめる。書き方は「`コード`（level。説明）」）:
  - 読み込みと入力: `CFN-ABSOLUTE-ROOT`（info。`root` が `--root-base` と別のドライブで、絶対パスで書いた）、`CFN-CDK-STACKNAME-DUPLICATE`（info。cdk.out で同じ stackName が複数あり、address には artifact の ID を使った）、`CFN-MALFORMED-RESOURCE`（error。リソースの形が誤り: 本体がオブジェクトでない、Type が無い、Fn::ForEach の形が誤り）、`CFN-NESTED-UNREADABLE`（error／warn。ネストスタックの子テンプレートを読めない（error）、見つからない（warn。黒箱のモジュールにする。7.4））、`CFN-NESTED-CYCLE`（error／warn。ネストスタックが自分自身を含む。子の展開で見つけたら error、出力をたどる途中なら warn）。
  - パラメータ: `CFN-UNRESOLVED-PARAM`（warn。値も Default も無い。使ったところごと）、`CFN-SSM-PARAM`（warn。SSM のパラメータ型。値は決まらない）、`CFN-PARAM-NOT-ALLOWED`（warn。渡した値が AllowedValues に無い）、`CFN-PARAM-UNUSED`（info。`--param`・`--param-file` で渡した名前が Parameters に無い）。
  - 評価: `CFN-UNEVALUATED`（warn。Fn::Base64・Fn::Cidr・Fn::Transform など評価しない値、決まらない式。値は `$unknown`）、`CFN-DYNAMIC-REF`（warn。`{{resolve:…}}`）、`CFN-UNDEFINED-REF`（warn。定義の無い名前への Ref・GetAtt・Sub・DependsOn、子に無い出力への参照）、`CFN-MAPPING-MISSING`（warn。Fn::FindInMap の引く先が Mappings に無い）。
  - 条件と ForEach（A4）: `CFN-CONDITION-UNKNOWN`（warn／info。条件の値が決まらない。Fn::If は warn、リソース・Export の Condition は info）、`CFN-UNDEFINED-CONDITION`（warn）、`CFN-CONDITION-CYCLE`（error）、`CFN-FOREACH-UNRESOLVED`（warn。Fn::ForEach の集まりが決まらない。×N で出す）、`CFN-FOREACH-DUPLICATE`（error。展開した名前が重なった。後のものは無視する）。
  - Export: `CFN-EXPORT-CONFLICT`（warn。同じ Export の名前が複数。最初のものを使う）。
- `diagnostics` は `result.json` にそのまま載せる。`error` があっても、読めた分の IR は出す（終了コードは PLAN 1.3 の 4 に従う）。
